An open-source AI agent for Kubernetes and DevOps

Ask in plain language why a pod restarts, which disk is filling or what changed in the last deploy. Griffin answers from live cluster data through typed tools — never from the model's memory — and tells you which path each answer came from.

What the Kubernetes AI agent can check

Cluster status and logs

Pod health across clusters, kubectl-style get on any resource, container logs, and disk usage inside a pod.

Metrics and dashboards

PromQL queries, and the exact query behind a Grafana panel, so the answer matches the dashboard your team already trusts.

Databases

SQL on CloudNativePG PostgreSQL clusters, read-only by default, with writes only after the owner approves.

CI/CD and GitOps

GitLab pipelines, commits, merge requests and file search; changes are proposed as draft merge requests, never merged silently.

Network and edge

DNS, HTTP and TLS probes, CDN cache and DNS settings, MikroTik routers.

Storage

S3-compatible buckets: list objects and show images, PDFs or logs inline in the chat.

Built for the day the cluster is down

Every cluster tool tries the public Kubernetes API first and falls back to SSH on a node when the API, the SSO in front of it or the ingress is broken. Each answer is labelled with the path that produced it, so an SRE knows whether it came from the API or the emergency route. Griffin itself depends only on the box it runs on, so it stays available to diagnose the outage it is part of.

Safe by construction

  • The process that runs the model has no shell and no infrastructure credentials; a separate broker holds them and exposes only typed tools.
  • Write tools are narrow: S3 is read-only, router changes touch only items Griffin created, GitLab changes are draft merge requests.
  • Irreversible actions wait for the owner's approval; unattended chains such as scheduled jobs refuse them. Every approval is audited.
  • Tool access is filtered per caller, so a colleague or another agent gets only the tools you granted.

Example questions

  • “Which pods are not ready on the production cluster, and why?”
  • “How full is the S3 volume on node 3, and what grew this week?”
  • “Why did yesterday's pipeline fail on the runner?”
  • “Is the site slow for users or just the internal hostname?”

Griffin runs on Claude, Cursor or any OpenAI-compatible model, including local models. Infrastructure tools appear only once you describe your clusters in config/site.json.
